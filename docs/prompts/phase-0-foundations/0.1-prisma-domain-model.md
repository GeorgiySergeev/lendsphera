## New models added by this step

| Model        | Purpose                                                         |
| ------------ | --------------------------------------------------------------- |
| `Product`    | Concrete sellable SKU (e.g. "Xenoprost Active") within Category |
| `Price`      | Append-only price history per (product, geo, validFrom)         |
| `I18nString` | Translation strings by (key, lang) for runtime + widgets        |

## Key FK relations added

| From       | Cardinality | To        | FK / on delete                                        |
| ---------- | ----------- | --------- | ----------------------------------------------------- |
| `Category` | 1──\*       | `Product` | `Product.categoryId → Category.id` (optional)         |
| `Product`  | 1──\*       | `Price`   | `Price.productId → Product.id` (cascade)              |
| `Geo`      | 1──\*       | `Price`   | `Price.geoId → Geo.id` (set-null)                     |
| `Landing`  | \*──1       | `Product` | `Landing.productId → Product.id` (set-null, optional) |

## Domain rules baked into schema

- `Price` is **append-only**: new row = new period; service closes prior open
  period by setting `validTo = new.validFrom` in one transaction.
- Active price resolver:
  `MAX(validFrom) WHERE validFrom <= :at AND (validTo IS NULL OR validTo > :at)`.
- `Landing.productId` is **nullable** to support legacy landings where product
  mapping is ambiguous (matched by `LegacyLanding.categoryHint`).
- `I18nString` is global (no `workspaceId`) — translations are shared across all
  landings in the system.
