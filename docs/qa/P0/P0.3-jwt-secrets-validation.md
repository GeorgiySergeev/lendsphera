## 🎯 ПРОБЛЕМА

### Текущее состояние (⚠️ ПРОБЛЕМНЫЙ):
```typescript
// apps/api/src/config/env.ts
JWT_ACCESS_SECRET: z.string().min(16).default("dev-access-secret-change-me"),
JWT_REFRESH_SECRET: z.string().min(16).default("dev-refresh-secret-change-me"),
````

### Почему это вредно

1. `min(16)` недостаточно (слабые значения пройдут)
2. `"dev-access-secret-change-me"` ровно 25 символов → `min(16)` пройдет!
3. На production без явной env var код использует **default значение**
4. Attacker зная defaults может forge любой JWT:

```javascript
const jwt = require("jsonwebtoken");
const token = jwt.sign({ sub: "attacker", role: "admin" }, "dev-access-secret-change-me");
// ✅ Token accepted by production API!
```

## 📋 ШАГ 3: Добавь custom superRefine логику

### 3.1 Обнови env.ts с блокировкой dev defaults

```typescript
import { z } from "zod";

// Known dev/test values that should NEVER be used in production
const BLOCKED_SECRET_VALUES = [
  "dev-access-secret-change-me",
  "dev-refresh-secret-change-me",
  "change-me",
  "secret",
  "test-secret",
  "temporary",
  "default"
];

export const envSchema = z
  .object({
    NODE_ENV: z.enum(["development", "test", "production"]).default("development"),
    PORT: z.coerce.number().default(4000),

    // JWT Secrets - must be strong and non-default
    JWT_ACCESS_SECRET: z.string().min(32, "Must be at least 32 characters"),
    JWT_REFRESH_SECRET: z.string().min(32, "Must be at least 32 characters")

    // ... rest of env vars
  })
  .superRefine((data, ctx) => {
    // ============ PRODUCTION-SPECIFIC VALIDATION ============
    if (data.NODE_ENV === "production") {
      // Check JWT_ACCESS_SECRET
      if (
        BLOCKED_SECRET_VALUES.some((blocked) =>
          data.JWT_ACCESS_SECRET.toLowerCase().includes(blocked.toLowerCase())
        )
      ) {
        ctx.addIssue({
          code: z.ZodIssueCode.custom,
          path: ["JWT_ACCESS_SECRET"],
          message: `JWT_ACCESS_SECRET contains a known development value. 
                 This MUST be changed for production. 
                 Got: "${data.JWT_ACCESS_SECRET.substring(0, 10)}..."
                 
Generate a strong random secret with:
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
        });
      }

      // Check JWT_REFRESH_SECRET
      if (
        BLOCKED_SECRET_VALUES.some((blocked) =>
          data.JWT_REFRESH_SECRET.toLowerCase().includes(blocked.toLowerCase())
        )
      ) {
        ctx.addIssue({
          code: z.ZodIssueCode.custom,
          path: ["JWT_REFRESH_SECRET"],
          message: `JWT_REFRESH_SECRET contains a known development value. 
                 This MUST be changed for production. 
                 Got: "${data.JWT_REFRESH_SECRET.substring(0, 10)}..."
                 
Generate a strong random secret with:
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
        });
      }

      // Check that secrets are different
      if (data.JWT_ACCESS_SECRET === data.JWT_REFRESH_SECRET) {
        ctx.addIssue({
          code: z.ZodIssueCode.custom,
          path: ["JWT_ACCESS_SECRET"],
          message: "JWT_ACCESS_SECRET and JWT_REFRESH_SECRET must be DIFFERENT values"
        });
      }
    }
  });

// Parse env variables
try {
  const config = envSchema.parse(process.env);
  console.log(`[ENV] Loaded config for NODE_ENV=${config.NODE_ENV}`);
  export const env = config;
} catch (error) {
  if (error instanceof z.ZodError) {
    console.error("[ENV] Configuration validation failed:");
    error.errors.forEach((err) => {
      const path = err.path.join(".");
      console.error(`  ❌ ${path}: ${err.message}`);
    });
    process.exit(1);
  }
  throw error;
}
```

### 7.1 Создай файл `docs/deployment-secrets.md`

```markdown
# Production Secrets Management

## JWT Secrets

When deploying to production, you MUST generate and set new JWT secrets.

### How to generate:

\`\`\`bash

# Generate access secret

ACCESS_SECRET=$(openssl rand -hex 32)
echo "JWT_ACCESS_SECRET=$ACCESS_SECRET"

# Generate refresh secret (MUST be different)

REFRESH_SECRET=$(openssl rand -hex 32)
echo "JWT_REFRESH_SECRET=$REFRESH_SECRET"
\`\`\`

### Where to set (platform-specific):

**Vercel/Netlify:**

- Go to Project Settings → Environment Variables
- Add JWT_ACCESS_SECRET and JWT_REFRESH_SECRET
- Mark as sensitive

**Docker:**

- Pass as env vars in docker-compose or kubernetes manifests
- Use secrets management (HashiCorp Vault, AWS Secrets Manager, etc.)

**GitHub Actions:**

- Add to repository secrets
- Reference as \`${{ secrets.JWT_ACCESS_SECRET }}\` in workflows

### Validation:

The application will FAIL TO START if production JWT secrets contain known dev values.
Example error:
\`\`\`
❌ JWT_ACCESS_SECRET contains a known development value. This MUST be changed for production.
\`\`\`

### Rotation:

To rotate secrets:

1. Generate new secrets
2. Update environment variables
3. Restart application
4. Old tokens will be invalidated (expect users to re-login)
```
