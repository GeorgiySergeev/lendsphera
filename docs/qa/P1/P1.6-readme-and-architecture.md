## Overview

LendSphera is a full-stack **landing page builder SaaS** built with:

- **Frontend:** Next.js 14 + React 19 (Editor & Runtime)
- **Backend:** NestJS + TypeScript
- **Database:** PostgreSQL 16 + Prisma ORM
- **Cache:** Redis 7 + BullMQ
- **Storage:** MinIO (S3-compatible)
- **Editor:** GrapesJS + Monaco Editor
- **Infrastructure:** Docker Compose, GitHub Actions, Playwright

## 🎯 Key Features

- ✨ **Drag-and-Drop Editor** - Intuitive GrapesJS-based canvas
- 🔒 **Real-time Locking** - Redis-backed pessimistic locking for concurrent editing
- 💾 **Auto-save** - Dirty flag-based autosave with lock heartbeat
- 📱 **Responsive Design** - Mobile-first responsive design system
- 🌍 **Multi-language** - i18n support (WIP)
- 🔐 **SOC2 Ready** - JWT auth, audit logs, role-based access
- ⚡ **FastAPI** - Sub-100ms response times with query optimization
- 🐳 **Cloud Ready** - Docker, Kubernetes, managed databases

## Data Model

### Landing

```sql
Landing {
  id            PRIMARY KEY
  name          Name/Title
  slug          URL-friendly slug (unique per geo)
  publicId      Public URL identifier
  status        DRAFT | PUBLISHED | ARCHIVED

  ownerId       User FK
  geoId         Geo FK (geographic market)
  categoryId    Category FK
  variantId     Variant FK (A/B testing)

  lockedById    User FK (NULL if not locked)
  lockExpires   DateTime (when lock TTL expires)

  currentVersionId  ← Current published version

  createdAt, updatedAt, deletedAt (soft delete)
}
````

### Version

```sql
Version {
  id            PRIMARY KEY
  landingId     Landing FK
  grapesJson    GrapesJS document (components, styles, assets)
  html          Rendered HTML (after GrapesJS compile)
  css           Rendered CSS
  customCss     User-added CSS

  isPublished   Boolean
  publishedAt   DateTime

  createdBy     User FK
  createdAt, updatedAt
}
```

### Lock (Redis)

Temporary entries:

```
landing:lock:{landingId} → userId
TTL: 120 seconds (refreshed every 80 seconds via heartbeat)
```

Enforced via Lua scripts (atomic compare-and-set).

## Data Flow

### Edit Flow

```
User edits component
    ↓
GrapesJS emits event (component:update)
    ↓
markDirty() called
    ↓
isDirty flag = true
    ↓
[Every 10 seconds]
    ├─ isDirty check (O(1))
    ├─ If YES: serialize() + send to API
    ├─ API saves to landing.currentVersion
    └─ Autosave status displayed in UI
```

### Publish Flow

```
User clicks "Publish"
    ↓
Frontend: POST /landings/{id}/publish
    ↓
Backend:
    ├─ Acquire exclusive lock
    ├─ Validate document
    ├─ Create new Version record
    ├─ Queue job: BuildAndPublish
    └─ Return with job ID
    ↓
Job Worker (BullMQ):
    ├─ Compile GrapesJS → HTML
    ├─ Extract CSS
    ├─ Minify & bundle
    ├─ Upload to S3
    ├─ Update landing.publicId metadata
    └─ Send webhook: "published"
    ↓
  User sees "Published" status
  Runtime can serve page from S3
```

### Lock Acquisition Flow

```
Frontend: POST /landings/{id}/lock
    ↓
Backend:
    1. Try acquireLock(key, userId) → Redis SET key userId NX EX 120
    2. If SUCCESS: Write to DB (lockedById, lockExpires)
    3. If FAIL: Check current owner
       - If owner == userId: refreshLock() (extend TTL)
       - Else: throw ConflictException
    ↓
Start heartbeat:
    ├─ Every 80 seconds
    ├─ POST /landings/{id}/lock/refresh
    └─ Backend: Lua script → atomic EXPIRE
    ↓
On page unload:
    ├─ POST /landings/{id}/lock/release
    └─ Lua script → atomic DEL if owner matches
```

## Concurrency Model

### Pessimistic Locking (Short-term Exclusive Access)

Only **one** user can edit a landing at a time:

```
User A locks landing → lock acquired
  (others can view, cannot edit)
User B tries to edit → error: "Locked by user A"
After 2 min idle → lock expires
User C now can lock
```

Fallback for v2: CRDT-based collaborative editing (Yjs).

## Authentication & Authorization

### JWT Strategy

1. **Login:** POST /auth/login → API returns { accessToken, user }
2. **Set Cookie:** Browser automatically stores `refreshToken` (HttpOnly, Secure, SameSite=Lax)
3. **Requests:** Frontend adds `Authorization: Bearer {accessToken}` header
4. **Refresh:** On 401, POST /auth/refresh → uses `refreshToken` from cookie → new accessToken

Tokens:

- **Access:** 15 min TTL, short-lived, in-memory
- **Refresh:** 30 days TTL, HttpOnly cookie, never in JS

### Global Auth Guard

All endpoints protected by default. Opt-out with `@Public()` decorator.

```typescript
@Controller('landings')
@UseGuards(JwtAuthGuard)  // Applied globally now
export class LandingsController {
  @Get('public/:publicId')
  @Public()  // Explicitly public
  getPublic() { ... }

  @Get()  // Implicit: requires JWT
  list() { ... }
}
```

## Performance Optimizations

### Query Optimization

Avoid N+1 queries:

```typescript
// ❌ BAD: N queries for N landings
landings.forEach(l => {
  const owner = await prisma.user.findUnique({...})
})

// ✅ GOOD: One query with relations
const landings = await prisma.landing.findMany({
  select: {
    owner: { select: { id, name } }  // Only needed fields
  }
})
```

### Autosave Optimization

Avoid stringify-every-10s:

```typescript
// ❌ OLD: Blocks thread
setInterval(() => {
  doc = JSON.stringify(editor.serialize()); // 5-50 MB
}, 10000);

// ✅ NEW: O(1) flag check
grapesEditor.on("component:update", () => (isDirty = true));
setInterval(() => {
  if (isDirty) serialize(); // Only once when needed
}, 10000);
```

Results: 4-10x faster, <50ms main thread blocking.

### Bundle Size

- GrapesJS (core): ~150 KB (gzipped)
- Monaco Editor: Lazy-loaded on-demand
- React Query: Tree-shaken
- Zustand: ~3 KB

Track with: `next build --analyze`
